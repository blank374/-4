# 任务三：多维路径集与近似评价

**更新：新版已通过带误差约束的OPEN标签合并完成全部270组合，详见 [优化方法与最终结果](task3_optimization.md)。下文保留初版 `--algorithm baseline` 的模型和实验口径，用于对照，不代表新版仍有49组未认证。**

## 建模选择

沿用任务二已验证的多目标 A* 框架，增加完整路径恢复、五维成本和可选的 ε 近似剪枝。二维、三维、五维共用一套实现，便于分析维度的影响。

也参考了你提供的 `task2_fast_exact.cpp` 的字典序搜索、有序二维skyline和初始可行解思路。任务二只需目标向量；任务三必须保存父标签与实际边。五维投影后还有四维，不能直接照搬三维程序的二维skyline结构就宣称支持五维。

不把“五维完整精确前沿”设为必须完成的主线。任务三允许近似，重点是给出可行的非支配候选路径，并说明质量、规模、时间和内存的取舍。代码也提供精确模式，但触及资源上限就报告未认证，不把截断结果标为完整前沿。

初版参考 NAMOA*dr 的降维检查和 NAMOA*dr-ε 的终点近似剪枝。后者在 [Zhang等，ICAPS 2022，A*pex论文第3页](https://cdn.aaai.org/ojs/19825/19825-40-23838-1-2-20220613.pdf) 中作为比较算法介绍。初版不合并标签；新版默认 `--algorithm apex`，增加可认证的OPEN合并，具体差异见优化说明。

## 题目约束

- 使用各城市 `queries_problem34.csv`，不能拿任务二的查询和结果替代。
- NY、BAY、COL各30组，分别计算m=2、3、5，共270个“查询×维度”组合。
- m=2优化c1、c2；m=3优化c1、c2、c3；m=5优化全部维度。
- 每条路径必须输出全部五项边成本之和及完整顶点序列，方向正确且不重复顶点。
- 相同参与目标向量保留一条代表路径；返回集内部去支配。

c1为距离、c2为时间、c3为起伏、c4为节点度相关成本、c5为边数。程序保留全部原始整数，未参与优化的维度也真实累加，不能填零。

```text
dataset,query_id,source,target,objective_count,solution_id,c1,c2,c3,c4,c5,path
```

同一城市、查询、维度内，solution_id从1连续编号。内部JSON额外记录CSR边编号，以准确核对平行边；正式CSV严格使用题目给定格式。

## 算法

### 下界和初始解

对每个参与目标，从终点运行反向Dijkstra，得到从节点v到终点的单目标下界 `h_j(v)`，满足一致性 `h_j(u) <= c_j(u,v)+h_j(v)`。

恢复各个单目标最短路，再补充归一化的加权和最短路，形成可行初始集。默认总共12次单目标/加权求解；权重随机数种子固定为3405，归一化分母为 `max(1,h_j(source))`。去除重复、支配后不一定有12条路径。

加权和只用于初始解和对照方法，可能漏掉非支撑Pareto点，不能单独保证覆盖前沿。其浮点权重不参与证书计算：后续使用的是恢复路径的真实整数成本。

### 局部精确剪枝

标签记录节点、五维累计成本、父标签和实际入边。OPEN按 `f=g+h` 字典序出队，内部顺序为c2、c1、c3、c4、c5；CSV列顺序不变。

一致性保证同一节点已出队标签的第一排序坐标不大于当前标签，故对CLOSED的支配检查可以省掉c2：

| 参与维度 | 局部结构 |
| --- | --- |
| 2 | c1最小值 |
| 3 | c1、c3有序二维skyline，二分查询 |
| 5 | c1、c3、c4、c5四维skyline，逐点检查 |

局部只做精确支配，没有对每段前缀加ε。五维的四维支配和标签数量仍可能昂贵；本方法不承诺多项式时间或固定内存。

### 用完整路径做ε剪枝

对前缀下界 `f=g+h`，仅当存在**同一条已找到的完整路径a**，满足

\[
C_j(a)\le(1+\varepsilon)f_j\quad\forall j\le m
\]

时才剪枝。任何补全路径b都满足 `f_j <= C_j(b)`，所以a已经ε覆盖所有这些补全。不能把不同路径的最小坐标拼成虚假的上界。

目标集只做精确去支配。如果见证a被新路径a′删除，则 `C(a′)<=C(a)`，旧覆盖关系仍成立。因此近似误差不会逐层累积。

ε最多支持6位小数，判断采用128位整数交叉相乘。下界某坐标为0时，覆盖见证对应成本也必须为0。

### 正确性与停止状态

ε=0时，局部支配保留不更差的代表，终点剪枝只删除已覆盖成本；OPEN耗尽即得到完整、成本去重的精确前沿。ε>0时，只有完整路径剪枝引入一次近似，OPEN耗尽后得到乘法ε覆盖。

边成本非负，环不能改善任一参与目标。返回已访问节点的搜索标签被该节点的局部skyline支配；恢复路径后程序还会检查重复顶点、实际入边与全部成本，外部脚本再独立核对。

| 状态 | 含义 |
| --- | --- |
| `exact` | ε=0且OPEN耗尽，完整精确前沿 |
| `epsilon_cover` | ε>0且OPEN耗尽，具有指定ε的全前沿覆盖保证 |
| `unreachable` | 反向最短路证明不可达，空集合 |
| `time_limit` / `label_limit` / `expansion_limit` | 当前非支配候选集，没有指定ε覆盖保证 |
| `seed_only` | 单目标/加权初始解对照，没有全局覆盖保证 |

近似返回集在**自身内部**非支配，不宣称其中每条路径都属于真实Pareto前沿。ε覆盖也不意味着每条路径各成本恰好增加ε。

## 实验与评价

批量入口先对全部270组合运行ε=0.20，再对每城官方查询0001、0015、0030比较ε=0.05、0.10、0.20和加权初始解，最后补全全部90组二维精确参考集。这些对照是按查询序号固定的首/中/末样本，**不是随机样本，不预设代表所有难度**。共441个不重复配置，所有触顶组如实保留，不替换查询。

指标包括路径数、展开数、耗时、峰值内存和乘法ε指标：

\[
I_\varepsilon(A,R)=\max_{r\in R}\min_{a\in A}
\max\left(1,\max_{j\le m}\frac{C_j(a)}{C_j(r)}\right)-1.
\]

分子分母均为0按1处理，分母为0而分子为正按无穷处理。越小表示覆盖参考集越好。

- 有同组精确结果时，R取真实精确前沿，标为 `exact`。
- 否则R取已测试配置的非支配并集，标为 `pooled_empirical`。它只能衡量已观察解，不能证明未知前沿质量。最丰富的配置可能得0，但不等于精确。
- 如果该组仅测试了一种配置，标为 `unavailable_single_config`，经验指标留空，不能把“自己覆盖自己”的0当成质量证据。
- `certified` 来自搜索结束条件，独立于经验指标。路径核验只证明路径和成本正确，不单独证明完整性。

`total_seconds` 包含图加载、预处理、搜索和整理，不包括JSON写出；`wall_seconds` 还包括进程运行和结果写出。`peak_rss_mb` 是单个独立工作进程从图加载开始的峰值。并行竞争会影响耗时，不应当作单核独占基准。

## 运行

Windows：

```powershell
.\build_task3.ps1
python verify_task3_solver.py
python run_task3.py --algorithm baseline --query-ids 0001 --epsilons 0.05,0.1,0.2 --baseline --exact-2d --output-dir results_task3_baseline_pilot
python verify_task3_results.py results_task3_baseline_pilot
```

Linux完整实验（从仓库根目录运行）：

```bash
TASK3_WORKERS=16 bash run_task3_batch.sh
```

该入口编译、穷举验证、运行全量及对照实验、核验并汇总。服务器必须同时有合并边表和 `queries_problem34.csv`。实际服务器地址、账号、密钥不写入仓库。

只运行一组五维：

```bash
./task3_solver --edges data/edges/edges_NY_5obj.txt --source 300 --target 169952 --objectives 5 --epsilon 0.2 --seeds 12 --max-seconds 30 --max-labels 12000000 --output tmp/task3_one.json
```

单组输出不覆盖已有文件。Windows将可执行文件替换为 `.\task3_solver.exe`。

普通批量脚本默认每组搜索60秒、200万标签；实验入口显式使用30秒、1200万标签。预处理时间另计；时间检查并非操作系统强制超时，可能略超时。标签上限也不是严格RSS上限，图和数组容量仍需额外内存。

初版输出位于 `results_task3/`。用于论文对照的原始断点、比较表和报告已从忽略规则中放出，未完成的 `.partial.csv` 仍忽略：

- `checkpoints/*.json`：完整路径、参数、输入/源码/二进制哈希和状态。
- `comparison.csv`：逐配置质量、规模、耗时、内存。
- `verification_report.json`：逐文件路径核验和哈希。
- `aggregation.json`：270组合覆盖情况与汇总CSV哈希。

同参数加 `--resume` 可复用断点，触顶结果也会复用。提高预算应改参数重新算，并非从旧OPEN继续。输入或二进制变化会生成新配置。不要同时启动两个控制器写同一目录；比较不同预算建议使用不同输出目录，避免汇总同一ε时有多个配置。

```bash
python3 run_task3.py --aggregate --exact-2d --export-epsilon 0.2 --output-dir results_task3
```

汇总会重新核验路径和输入，并逐行对照CSV。这里的 `--exact-2d` 选择二维精确集，三维、五维选ε=0.20配置；`aggregation.json` 记录各维度参数。省略该选项则各维度都选择给定ε的配置。

只有270组合均有各自配置的证书才生成 `result3_研XXX.csv`；否则生成 `result3_研XXX.partial.csv`，保留所有触顶状态。这个命名限制比题目对近似候选的要求更保守，用于防止误报已认证完整结果。

实际结果见 [任务三实验记录](task3_validation.md)。若五维大量触顶，后续应考虑可认证的A*pex合并或更高效的四维支配结构；不能随意每节点只留K条，或悄悄增大ε后宣称原精度已经完成。
