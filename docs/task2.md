# 任务二：三目标精确 Pareto 前沿

正式入口为 `task2_exact.cpp`。目标是为固定查询求得所有不同的 Pareto 最优目标向量，三个目标分别为通行距离、时间、地形起伏，均最小化。

## 模型与正确性

有向图每条边有非负整数成本向量 `c(e)`。路径成本逐边相加。同一目标向量只保留一条；任务二不要求输出路径。

算法采用多目标 A* 的字典序搜索与二维支配检查，结合所提供的 `task2_fast_exact.cpp` 参考方法整理实现。没有近似支配、标签数量截断或加权和替代完整前沿。

1. 对终点运行三个反向 Dijkstra，得到每个节点各目标的剩余成本下界 `h(v)`。每一维满足一致性：`h_j(u) <= c_j(u,v) + h_j(v)`。
2. OPEN 按 `f = g + h` 的三维字典序排序。因为下界一致，沿扩展边的各维 `f` 均不减。
3. 同一节点已经弹出的标签，其第一维 `g` 不大于以后检查的标签，因此只需检查后两维即可判定支配。已弹出的终点解同样可以通过后两维过滤之后的 `f`。
4. 二维前沿按第二维递增、第三维严格递减保存。二分查找支配者，插入时删除被覆盖的连续区间。查询为 `O(log k)`，连续数组插入和删除最坏为 `O(k)`。
5. 初始种子不满足弹出顺序限制，必须用完整三维比较 `seed <= f`，不能提前放入二维终点索引。种子只是可行上界，最终与搜索发现的解合并后精确过滤。
6. 只有 OPEN 耗尽才宣告完整；不可达时前沿为空，`s=t` 时为零向量。

同节点更优前缀加上相同后缀不会变差，因而支配删除是安全的。边权非负，含环路线可以删环而不增成本；全零环只产生相同向量。所以最终非支配向量都存在不重复节点的路径代表，无须保存全部路径。

前驱恢复保存实际边，能够区分平行边。内部计算使用64位整数，并检查输入成本范围，拒绝无法保证精确整数运算的输入。

## 目标顺序

支持 `123,132,213,231,312,321`。例如 `213` 表示内部先比较时间，再比较距离和起伏。输出始终还原为原始 `c1,c2,c3`，不交换 CSV 列含义。

排序只改变搜索效率，不改变精确答案。36,000次随机图搜索覆盖六种顺序；正式90组结果使用213。

## 运行参数

| 参数 | 含义 |
| --- | --- |
| `--root DIR` | 数据根目录，默认当前工作目录 |
| `--dataset NY/BAY/COL` | 指定城市；不设置则全部城市 |
| `--query-id ID` | 指定原查询表中的ID，不重新编号 |
| `--max-queries N` | 每城市仅执行前N组匹配查询，供诊断使用 |
| `--order` | 内部目标顺序，默认123 |
| `--seed-count 3..10` | 可行种子数，默认3；额外种子仅作为剪枝上界 |
| `--max-seconds N` | 每组搜索预算，含种子处理，不含读图与反向Dijkstra；0为无限制 |
| `--max-expanded N` | 扩展数上限；0为无限制 |
| `--max-open N` | OPEN条目数上限；0为无限制；不是进程硬内存上限 |
| `--output-dir DIR` | 结果目录，默认 `results_task2_exact` |
| `--researcher XXX` | 队号占位符；支持字母、数字、下划线和连字符 |
| `--resume` | 恢复完整查询；未完成查询重新搜索 |

单进程执行按终点分组，只保留一个终点的反向距离缓存。不要让多个进程写入同一个输出目录；并行运行请使用正式服务器脚本，由独立查询目录汇总断点。

## 完整性状态与输出

- 全部输入查询完成时才生成 `result2_研XXX.csv`。
- 部分完成时只生成 `.partial.csv`，其中也只包含已经完整求出的查询。
- 时间、扩展数、队列预算触发时，不保存该查询的部分向量，也不生成完成断点。
- `--max-queries 1` 返回成功只表示所选查询范围完成，不表示全部90组完成。
- `task2_status.csv` 的完成状态为 `complete` 或 `unreachable`；其他状态仍未完成。
- 返回码0：本次所选范围完整；2：达到资源限制；1：输入或运行错误。

断点使用临时文件加原子替换，包含版本、输入指纹、城市、查询ID、源点、终点、向量和统计。输入指纹用于检测误用旧数据，不是密码学证明。断点被截断、输入改变或查询不匹配时拒绝恢复。旧求解器的完成标记不能作为新实现的断点。

`search_seconds` 不含读图和缓存反向Dijkstra。内存统计是在搜索结束前采集的进程累计峰值，不能视为后续CSV汇总阶段的完整内存测量。

## 验证范围

- 2000个随机多重图 × 六种顺序 × 三种种子设置，与独立简单路径穷举对照。
- 覆盖零权重、零环、平行边、不可达、起终点相同。
- 单独检查4096个全部非支配向量的构造图及资源限制。
- CLI测试覆盖中文路径、完整256向量集、续算、拒绝覆盖、损坏断点和输入指纹变化。
- 全部90组结果在Linux服务器和Windows本机分别完成文件核验。

详情见 [验证记录](validation.md)。最终文件核验不能单独证明搜索完整性；完整性依据是算法不变量和耗尽OPEN的终止条件。
